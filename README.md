# soshiki-zu（組織図）

Claude Code の MOD。「秘書」ひとつを入口にした個人の AI 組織（秘書のフォルダ。例：`notes`）の組織図を右のペインに出し、いま動いている係と現場のセッション、生活の記録のボタンを1つのペインで見せる。秘書のテンプレート（secretary-template）と一緒に使う形。

- **ペット**（いちばん上）：ドット絵のマスコット（横 48px）。何も動いていないと寝る、係・現場のセッション・秘書のターンが動いていると作業、係が終わると喜ぶ、失敗すると転ぶ（8秒）。横に一言（「係 1 · 考え中」「○○ がおわった」「すやすや」）
  - 横の「あそぶ」でジャンプのミニゲームになる（色の箱、1ドット＝横2マス。クリックかスペースでジャンプ）。係が終わるとゲームの上に「★ ○○ がおわった」が出る。「もどる」でマスコットに戻る。さいこう点は次のセッションにも残る。マスコットの絵（SVG）は押せる部品にできないので、押すのは横の「あそぶ」
  - キャラは `hooks/pet/chara.ts` の1か所（既定は自作の「もち」）。設定の `charaFile` に同じ形の JSON（`name`・`palette`・`eye`・`stand`＝16×12 の文字の並び）の絶対パスを書くと差しかわる。名前（マスコットにマウスを乗せると出る）も JSON の `name` で決める。ペットの部分は `hooks/pet/` にまとめてある（外し方はそのファイルの先頭）
- **あなた待ち**（ペットの下。待っている物があるときだけ）：件数だけ出し、押すと1件1行（どこ＋なぜ）。1件を押すと「なぜ・やること」と、打つコマンド（そのままの形）と「写す」ボタン
  - 読む物：部門のファイル `status/<部門名>.md` の「本人の返事待ち：…」「本人の手待ち：…」の行と「## 本人の返事待ち」の節。台帳（`### 名前` の「場所：`フォルダ`」）の `HANDOFF.md` の、いちばん新しい「本人に聞きたいこと／本人に聞くこと／本人が打つ／本人がすること」の節（見出しに「済」があれば読まない）。止まって2時間以内の現場のセッション（アプリは「許可の画面で止まっている」かまでは教えないので「返事待ちかも」）
  - 秘書のターンの終わりと、セッションの始まりに読み直す
- **使用量**（あなた待ちの下の1行）：「5h ███░ 85% ·16:40 ／ 週 ██░░ 66%」（· のあとは戻る時刻）。8割をこえた枠は黄、95%をこえたら赤（色は合図だけ）。押すと開いて、週の戻る日時・週のモデル別・秘書の会話の長さとこのセッションの料金・動いている現場のセッションの会話の長さ・終わった係のトークンが出る。ペインの文字は、数字・名前・状態だけにしてある（くわしい説明は、印にマウスを乗せたときと、開いたときだけ）
  - 数字はエンジン（`$.session.usage()`：5時間・週の枠、会話の長さ、料金）と、アプリの読むだけの道具（`get_usage`：週のモデル別、ほかのセッションの会話の長さ）から取る。取れないものは「取れない」と出す。推測の数字は出さない
  - 係のトークンは、係のターンが終わったときにエンジンが数えた分（入力・キャッシュ・出力の合計）。動いている間の数字は取れないので出さない
  - ほかのセッションの「会話の長さ」は、そのセッションがいま文脈に持っているトークンの量で、使った量の合計ではない。アプリが教えてくれるのは、そのセッションが動いている間だけ
- **いま動いているもの**：上に別の欄は置かず、組織図の中の回る印で見る（動いている係・セッションと、その上の秘書・部門・外の現場）。係の名前を押すと、何の作業か・出力先と「やりとり」（係の画面を開く）が下に開く。セッションの名前を押すと題名が開く。組織図に出ない物（役割カードの無い係など）だけ、組織図の上に1行ずつ出す
- **最近**：終わった係を3件まで、1件1行。状態は印（✓ 完了・半分 一部・× 失敗・‖ 中断）、かかった時間・終わった時刻・トークン。行を押すと、その係のやりとりの画面を見られる。見出しを押すと閉じる
- **組織図**：つながった線でつないだツリー（デスクトップは本物の細い線で、最後の枝は角が丸い。ターミナルは ├─ └─ │ の文字）。線は文字より薄い灰で、動いているものへ続く枝だけ橙。秘書と「外の現場」がいちばん上に並ぶ（現場は秘書の下の係ではない。「本人」の行は出さない）。動いている係・セッションと、その上の秘書・部門・外の現場の行には回る印
  - 秘書 → 部門（PM）→ 係。部門は `status/index.md` の表の左の列から読む。部門は最初閉じていて、係の数だけ出る。名前を押すと開き、「動」の1行（`status/index.md`）と係が出る。係が動き出すと、その部門の枝は自動で開き、横に動いている数、係の行は橙の回る印になる
  - 部門の印は名前の言葉で選ぶ（「学」→ 本、「家」「生活」→ 家、「制作」「趣味」→ 枠、「仕事」「開発」→ 箱、ほかはフォルダ）
  - 外の現場 → いまのセッション（動いている／止まっている）と、台帳にある残りの現場。動いているセッションがあれば自動で開く
- **記録**（組織図の下。`status/生活.md` があるときだけ）：日付と時刻、次の予定（「家を出る あと 1:33 · 17:20」。残り30分で橙）、その下に記録のボタン。済んだものは薄く、時刻（「なし」なら なし）が出て、押せない（二重に送らない）。目安を過ぎたものは橙
  - 毎日のボタンはいつも出し、「間隔」の表のもの（洗濯・ごみなど何日かごとのもの）は「ほか」を押すと開く（ほかの中に橙があれば「ほか」も橙）
  - 押すと、名前だけの合図（例：「昼」）を本人の送信として送る。書くのは秘書のフォルダの記録のフック（いまの時刻で書く）。時刻をずらす・「なし」にするときは打つ（例：「昼 12:10」「朝 なし」）
  - 記録のボタンの MOD（kiroku-botan）と同じ読み方なので、こちらだけで足りる（kiroku-botan のペインは閉じておけばよい）

`/soshiki` でペインを開き直す（名簿を読み直す）。`roles/roster.md` の無いフォルダで開いたセッションでは開かない。

`/reload-plugins` のあとは、ペインがいったん消える。アプリは、頼まれずに開くペインを、画面が広いとき（144文字分以上）しか出さない。そのため、狭い画面では本人が次に何か送ったときに開き直す（すぐ見たいときは `/soshiki`）。本人が × で閉じたときは開き直さない。`/soshiki` で戻る。

動いているときは、だいたいこう見える（デスクトップでは ◌ や ▾ の所が線のアイコン）:

```
5h ███████░ 85% ·16:40  週 █████░░░ 66%
◌ 秘書
├─ ◌ ▾ 仕事  1                                 ← 橙
│  │  動：試作A（…）・試作B（…）
│  ├─ 判定役
│  └─ ◌ 市場調査係  2分                        ← 橙。押すと作業の内容
├─ ▸ 学び
├─ ▸ 家
└─ ▸ 全部門  2
◌ ▾ 外の現場  1
├─ ◌ ehon
└─ ⏸ kakeibo  5分

10/23（金） 15:47  家を出る あと 1:33 · 17:20
朝 なし  昼 13:00  夜  ▸ ほか                 ← 済は薄く、目安超えは橙
```

## 読むファイル（秘書のフォルダの中。どれも読むだけ）

パスはすべて作業フォルダからの相対。MOD の中に、決まった部門名・パス・記録の項目は入っていない。

| ファイル | 読む物 | 無いとき |
|---|---|---|
| `roles/roster.md` | 係の表（係名／立場／使う部門／役割カード）。どの部門にも入らない係は「全部門」 | ペインを開かない |
| `status/index.md` | 表の左の列が部門、2列目が「動」の1行。「詳細」の列が別のファイル（`org/design.md` など）を指す行は部門ではないので出さない（詳細が空か `status/<部門名>.md` の行だけ） | 名簿の「使う部門」から部門を作る |
| `status/<部門名>.md` | 「## 依頼中」（秘書が立てた現場：`- 日付 名前（別名）：何の作業か`）と「## 台帳」（`### 名前 — 部門`）。どの部門のファイルに書いてもよい | 外の現場は空 |
| `status/生活.md` | 記録の「声かけ」（目安の時刻）・「間隔」（何日ごと。ここの項目は「ほか」）・「定例」（時刻のある行は次の予定）。任意で「## ボタン」の表（`\| 項目 \| まとまり \| なしの言い方 \|`）を置くと、その順でボタンを出す | 記録を出さない |
| `.claude/scripts/life-log.ps1` | 記録のフックが受け取る合図の一覧（`$items = @('朝','昼','夜')`）。「## ボタン」の表が無いときは、これが毎日のボタンになる | 毎日のボタンは無し（間隔の項目だけ） |
| `journal/記録/YYYY-MM.md` | 今月と先月の記録（`- 日付 時刻 項目 [メモ]`。メモが「なし」ならしなかった） | まだ記録が無い |
| `status/締め切り.md` の「## 予定」 | `\| 日付 \| 部門 \| やること \| 状態 \|` の7日以内・未済（「16:00まで」があればその時刻、無ければ 23:59） | 読まない |
| `status/学業.md` の「## 個別」 | 前からの形（`\| 日付 \| 科目 \| 出すもの \| 状態 \|`）。あれば同じように読む | 読まない |

ボタンを押して送る合図は、記録のフックが受け取る物だけにする（`## ボタン` の表に書く項目も、フックの合図か「間隔」の表の項目にする）。

## どうやって知るか

- 係の一覧：`roles/roster.md` の表。秘書のターンが終わるたびに読み直す
- 係が呼ばれた：Agent ツールが係を始めるとき（`agent.spawn`）。係名はプロンプトの「役割カード: …/roles/<係名>.md」から、出力先は「出力先: work/…」から取る。カードの無い呼び出しも「役割カードなし」として出る
- 係が終わった：係のターンの終わり（`turn.complete`）。返事の先頭の「状態: 完了|一部|失敗」を読む。取りこぼしても、5秒ごとにエンジンの係の一覧と突き合わせて「終わった」にする
- 現場のセッション：デスクトップアプリのセッション一覧（`list_sessions`、読むだけの道具）を15秒ごとに聞き、秘書が立てたもの（立てた元がある・しまっていない）だけ出す。現場の名前は「## 依頼中」の行と結び付けて決める（セッションの短い名前・フォルダ名・題名に、依頼中の名前が入っているか）
  - アプリが教えてくれるのは「動いている（いま返事を作っている）か、いないか」だけ。止まっているのが「本人の返事待ち」なのか「終わった」のかは見分けられないので、「止まっている（返事待ちかも）」と、止まってからの時間で出す
  - その道具に許可が要る設定だと、15秒ごとに許可の画面が出てしまうので、呼ばない。そのときは「依頼中」の行だけを出し、「動いているかはわからない」と書く。出したいときは、自分の設定（`~/.claude/settings.json`。秘書のフォルダの設定ではない）の `permissions.allow` に `mcp__ccd_session_mgmt__list_sessions` を足す
  - ターミナルや `claude -p` など、デスクトップアプリの外のセッションにはこの道具が無いので、「依頼中」の行だけになる
- 記録：1分ごと・本人の送信のあと（フックが書いたあと）・秘書のターンの終わりに読み直す

秘書のフォルダのファイルは読むだけ。そのフォルダの設定（`.claude/`）は変えない。フックは MOD の中にあるので、秘書のフォルダ側に登録する物は無い。

## 入れ方

リポジトリ：`taku3i0317-collab/soshiki-zu`

ターミナルの Claude Code で:

```
/plugin install soshiki-zu --marketplace taku3i0317-collab/soshiki-zu
```

シェルから:

```bash
claude plugin install soshiki-zu --marketplace taku3i0317-collab/soshiki-zu
```

デスクトップアプリ（`/plugin` が使えない所）: 入力欄の横の + → Plugins → Add marketplace に `taku3i0317-collab/soshiki-zu` → Add plugin で soshiki-zu。

「Add marketplace?」には `y`、範囲は一番上の user を Enter。入れたあと、秘書のフォルダの新しいセッションを開く（開いているセッションなら `/reload-plugins`）。右に「組織図」のペインが出る。新しいバージョンを取りこむときは `claude plugin update soshiki-zu` のあと `/reload-plugins`。

**直しながら使うとき**（フォルダから読む入れ方。直したあとは `/reload-plugins` だけでよい）

```bash
git clone https://github.com/taku3i0317-collab/soshiki-zu.git
```

```bash
claude plugin marketplace add ./soshiki-zu
```

```bash
claude plugin install soshiki-zu@soshiki-zu
```

## 確かめ方

1. 秘書のフォルダのセッションで `/reload-plugins`（または新しいセッション）。右に「組織図」が出て、`status/index.md` の部門が閉じた状態で並ぶ
2. `status/生活.md` があれば、組織図の下に記録が出る。まだのボタンを押すと、入力欄からその名前が送られ、ボタンが薄くなって時刻が出る
3. 「現場のセッション」に、秘書が立てたセッションが出て、動いているものは橙になる
4. 係を呼ぶと（例：「市場調査係で〇〇を調べて」）、「いま動いている」に回る印で出て、組織図のその部門の枝が開き、係が橙になる。返事の「状態:」が「最近」に出る

自動のテスト（ファイルとセッション一覧を小さな見本に置き換えて、ターミナルとデスクトップの両方で描く）:

```bash
claude plugin test .
```

## 見た目の決まり

kiroku-botan と同じ：線のアイコン（形は [Lucide](https://lucide.dev)、ISC ライセンス）、色は合図だけ（橙＝動いている・目安超え、赤＝失敗、黄＝一部、ほかは灰）。ペットを上に、いちばん知りたい「いま動いている」をその下に、動かない組織図をそのあとに、押す物（記録）をいちばん下に置く。行のあいだを空けないので、罫線がつながって見える。
